## 问题与证据

| 问题 | 复现场景 | 修复方式 |
| --- | --- | --- |
| 不完整参数失真 | 仅修正命令名时，`mytool  'a   b` 的参数空白被压缩 | 在原始字符串中替换首个命令词 |
| 包装命令误改 | `env git status` 在 shell 解析成功后仍进入文本回退，可能命中 `env` 的用户规则 | shell 解析成功即返回该路径结果 |
| 连字符建议截断 | Git 将 `cherry-pik` 建议为 `cherry-pick`，旧解析器却生成 `git cherry` | 完整捕获建议词并验证词尾边界 |
| 通用提示定位歧义 | `poetry --directory addd addd requests` 的目录名被替换 | 检查静态词唯一性，放弃可能属于选项值的目标 |
| 组合短选项误改值 | `sudo -nu gti git status` 会将用户名 `gti` 改为 `git` | 逐个识别短选项，消费所需的内联或独立参数 |
| 赋值遮挡命令 | `env MODE='hello world' gti status` 无法定位 `gti` | 从语法中识别赋值名称，保留值和引号 |
| 包装器分隔符混淆 | `command -- gti status`、`env -- MODE=prod gti status` 无法修正 | 明确结束选项解析，继续识别赋值和可执行文件 |
| 错误词被截断 | `tool remote remote.list` 的报错指出 `remote.list`，实际修改了 `remote` | 完整捕获单引号、双引号、反引号或不带引号的错误词 |
| 数据参数误改 | 通用提示将 `tool -- file remote.list` 的普通数据替换 | 拒绝 `--` 后的目标，保留分隔符前的合法修正 |
| 内联长选项阻止修正 | `poetry --directory=project addd` 被视为选项值歧义 | 明确带内联值的长选项不消费下一个参数 |
| 本地文档干扰验收 | Git 忽略的文档仍被 `make markdown-lint` 扫描 | 使用以 NUL 分隔的 Git 文件清单，保留新文件和特殊文件名 |

证据来自当前源码、新增测试的修复前失败输出、本机 Git 的真实报错，以及本地校验结果。
GitHub 仓库、开放 PR、最新 Release 和 Actions 设置于验证当日通过 `gh` 读取。
没有合入其他依赖 PR，没有替换依赖或提升最低 Go 版本。

## 测试范围

相对基线新增 19 个测试函数，包括首轮的 60 多个场景和后续组合验证：

- 用户规则、历史记录、内建规则与不完整参数中的空格、制表符、换行和非 ASCII 文本。
- `env` 包装命令、已正确命令及仍需修正的被包装命令。
- Git、Docker、npm 的连字符建议，以及问号等既有提示格式。
- 同名目录与子命令、引号内重复词、单独选项值、明确和不明确的通用提示。
- 拒绝截断带路径分隔符、shell 运算符、变量或额外后缀的建议词。
- 一万个带引号参数的保真检查。
- CLI 的 sudo 包装、复合命令、重定向，以及采集真实 Git 报错后完成纠错的端到端测试。
- Markdown 清单中的忽略文件、已跟踪的忽略文件、新文件、空格文件名、连字符开头文件名，以及失败退出码传播。
- 112 组包装器、组合选项、分隔符和七种赋值形式的交叉矩阵；每组同时检查错误命令可修正、正确命令不被改写。
- 14 种包装命令写法分别验证普通修正、仅命令名修正、候选排序及正确命令保持不变。
- 七种包装表达式在真实 Bash 和 Zsh 中执行，检查环境变量值与参数边界；两种动态值场景验证分析阶段不会执行命令替换。
- 一千个连续赋值的容量场景，以及普通模式、候选菜单对用户名和变量名的误修防护。
- 完整错误词、`--` 数据边界与内联长选项的正反例。
- 未加引号动态值、数组、间接展开和本地化引号的保守处理；真实 Bash 用例证明展开可能产生实际可执行文件，后续拼错形式的词此时属于数据参数。

## 平台与未验证项

- macOS arm64：运行完整本地测试和候选二进制版本输出检查。
- Linux amd64/arm64、macOS amd64、Windows amd64/arm64：交叉编译通过，不等同于在对应操作系统上运行完整测试。
- 本机没有 PowerShell，相关集成测试按既有条件跳过；Windows 专属快速安装运行测试同样跳过。Bash、Zsh 和 Fish 集成在本机执行。
- sudo 场景验证语法定位和 CLI 输出，没有执行真实提权；环境变量与参数的运行语义由 Bash/Zsh 配合真实 `env` 验证。
- 并发检查采用 Go race；长参数测试覆盖输入容量，重复回归检查覆盖稳定性。
- 未执行独立的高并发压力、分布式混沌或跨平台性能比较；本次修改没有引入后台服务或分布式组件。
- 此次测试目标采用项目的总体覆盖率门槛，92.9% 不代表每个包均达到 90%。
- 首次全量 E2E 在沙箱中因本地 HTTP 监听被禁止而失败；允许回环监听后完整重跑通过。
