# v1.8.3 发布说明

本版本修复命令纠错时的参数保真和错误提示定位问题。

## 修复内容

- Git 提示中的 `cherry-pick`、`checkout-index` 等子命令保持完整；Docker 和 npm 的连字符建议同样不再截断。
- 通用解析器检查错误词是否唯一，识别静态引号中的重复词，并避免将未知选项的值作为修正目标。
- 通用提示未指出错误词时，只尝试紧跟命令名的普通参数，避免将 `--directory` 后的目录名替换为子命令。
- 仅修正命令名的内部接口保留未闭合引号后的空白、制表符和换行；shell 解析成功后不再回退改写 `env` 等包装命令。
- 清理旧的参数重建函数，补充真实 Git 报错、包装命令、复合命令、重定向和长参数列表的回归测试。
- `make markdown-lint` 使用 Git 文件清单，包含未忽略的新文档，并正确处理带空格或以连字符开头的文件名，避免本地忽略文件干扰验收。

## 行为与兼容性

无迁移，直接替换二进制。配置、历史记录和用户规则格式不变，模块最低 Go 版本保持 1.26.3。
通用提示存在歧义时会放弃该提示；其他纠错阶段仍可继续工作。
构建工具链使用 Go 1.26.6。

## 发布与回滚

本次先提交修复 PR 并准备 GitHub Release 草稿，不合并 PR、不发布正式标签。
发布候选版本为 v1.8.3；在 PR 合入后，应以合入提交重新完成本地验证与构建，再发布正式标签及附件。
不得将 PR 分支的候选二进制误认为主分支正式制品。

割接窗口：PR 合入、最终提交本地门禁通过后执行；CLI 无服务停机要求。
替换前保留当前二进制，结束正在运行的 `typo` 进程，再安装新版本。
回滚时重新安装 v1.8.2 二进制并保留原配置、历史记录和用户规则，无数据迁移脚本需求。

验收命令、平台范围和限制见 [验收记录](v1.8.3-validation_CN.md)。
