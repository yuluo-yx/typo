# 命令匹配优化基准

验证日期：2026-09-06。主机：Apple M4，darwin/arm64；工具链：Go 1.26.6。

## 方法

匹配代码基线为 `1db12ac`，使用本次新增的 `BenchmarkCommandMatching` 在优化前后运行相同输入。
词库包含 10,000 个 `custom00000` 至 `custom09999` 命令；采用默认 QWERTY 权重、相似度 0.6 和最大编辑距离 2。
每个场景运行 5 次，以下为中位数。命令如下：

```bash
GOMAXPROCS=1 mise exec go@1.26.6 -- go test ./internal/engine \
  -run '^$' -bench '^BenchmarkCommandMatching$' -benchmem -benchtime=100ms -count=5
```

## 结果

| 输入 | 优化前 ns/op | 优化后 ns/op | 优化前 B/op | 优化后 B/op |
| --- | ---: | ---: | ---: | ---: |
| `custom05000` | 22,185,021.000 | 6.198 | 1,223,644 | 0 |
| `custom0500x` | 21,979,868.000 | 2,353,813.000 | 1,231,420 | 311,055 |
| `unrelatedxx` | 22,381,733.000 | 13,471,271.000 | 1,240,393 | 320,034 |

`custom05000` 精确命中，优化后直接查询索引且零分配；`custom0500x` 需要模糊匹配；`unrelatedxx` 没有达标候选。
性能变化来自最佳候选单次扫描、规则优先级缓存、精确命中快速返回，以及距离计算跳过公共前后缀。
这是进程内匹配函数基准，未包含 CLI 启动、PATH 扫描或终端交互，不能换算成整体命令提速。
原始日志保存在本次工作区 `.cache/release-v1.8.2-matching-before.log` 和 `.cache/release-v1.8.2-matching-after.log`。

## 正确性验证

- 未达标近邻不再遮挡达标候选；无结果时保留拒绝原因。
- 内建规则保留已知可执行文件；显式用户规则仍可覆盖。
- 极大编辑距离不会造成长度索引溢出。
- 使用独立完整矩阵，对三种键盘布局及 Unicode、公共前后缀样本比对距离结果。
- 规则权重缓存覆盖新增、替换、删除、启停及写入失败后的回滚。
